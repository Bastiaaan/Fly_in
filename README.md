# Fly in

## Description

Fly in is a 42 project that combines a Python-based map parser with a C++ simulation and graphics renderer.

The purpose of the project is to let the user select a difficulty and a map, parse the raw map data into JSON, and then run a C++ simulation that visualizes the result. The pipeline is organized as follows:

- Python handles the extraction and transformation of map files located under `maps/<difficulty>/<map>.txt`
- The parser converts the selected input into a JSON representation
- The C++ program loads the generated JSON and simulates the algorithm while rendering the visual output

This architecture separates data preparation from execution: the parser prepares structured data, while the C++ program handles simulation logic and rendering.

The project follows the typical 42 workflow of building a parser, assembling the simulation, and validating the result by running the compiled binary against the generated map data.

## Instructions

### Requirements

- Linux environment
- Python 3.10+
- C++ compiler (`g++` or `clang++`)
- `make`
- Terminal access

### Project structure

A typical project layout is:

```text
fly_in/
├── Makefile
├── parser/
│   ├── Makefile
│   ├── pyproject.toml
│   ├── .venv/
│   ├── src/
│   └── result/
├── maps/
│   └── <difficulty>/
│       └── <map>.txt
├── src/
├── include/
├── reference/
├── obj/
├── fly_in
└── ...
```

The important parts are:

- `parser/` contains the Python parser and its dependencies
- `maps/` contains the user-selectable raw map files
- `obj/` stores the compiled C++ object files
- the root `Makefile` orchestrates installation, build, run, and cleanup steps

### Install and build

Before the program can be executed, the project must be installed and built with:

```bash
make
```

This step performs the following tasks:

- creates the Python virtual environment inside the `parser/` directory
- installs the parser dependencies such as `pydantic`, `numpy`, `mypy`, and `flake8`
- compiles the C++ files used by the simulator
- stores the generated object files in the `obj/` directory
- produces the executable binary in the project root

This is the required preparation step before any execution.

### Run the project

After the installation/build step is complete, the program must be run with:

```bash
make run
```

This command is responsible for the full execution flow:

1. it cleans the previous parser output in `parser/result/`
2. it redirects to the parser project and runs its local `make run`
3. the user selects the desired difficulty and map
4. the parser converts the chosen raw map file into JSON
5. the C++ simulator is executed with the generated JSON data
6. the visual simulation is rendered

In other words, the workflow is:

```bash
make
make run
```

and the parser executes first, followed by the simulation.

### Map format

The project expects raw map files stored under:

```bash
maps/<difficulty>/<map>.txt
```

These text files are parsed into JSON before being used by the C++ simulation.

### Clean generated artifacts

To remove compiled object files and parser cache artifacts, run:

```bash
make clean
```

This removes compiled files from `obj/` and removes Python cache files generated by the parser.

For a full cleanup, run:

```bash
make full_clean
```

This removes the compiled outputs, the executable, the parser virtual environment, and the parser cache files.
